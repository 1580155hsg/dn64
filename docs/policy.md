# DN64 分配政策

## 资源范围

- ASN：`4206400000`–`4206409999`，属于 RFC 6996 的四字节私有 ASN 空间。
- IPv4：`10.64.0.0/16`，当前分配长度固定 `/24`。
- IPv6：使用 RFC 4193 的本地分配 ULA，成员独立随机生成 40-bit Global ID，申请 `/48`。使用 `./new-registration` 或 `python3 utils/registry.py ula`；不要仅为好记而选择 `fd64::/48`。
- DNS：内部 `dn64` 命名空间。正式接入 DNS 服务前，仓库只保存委派声明。

`fd00::/8` 注册对象定义 ULA `/48` 的允许范围；它不是对该地址空间的独占分配。这里只检测 DN64 注册库内的冲突，不能证明与所有其他网络不冲突。跨社区互联另行协调，DN64 资源不应向公网传播。

资源池由 `status: ALLOCATED` 对象描述，成员网段使用 `status: ASSIGNED`。当前不支持嵌套资源池；默认由 DN64 直接分配给成员。不同成员的分配不能重叠，路由必须包含于已分配的网段，且维护者必须拥有前缀和 origin ASN。

## 申请与审核

通常每位参与者先申请一个 ASN、一个 IPv4 `/24` 和一个 IPv6 `/48`。数量与参与目的由维护者人工审核；自动检查负责资源合法性、冲突和授权，不按自然人自动判断身份或配额。

PR 未合并前不拥有资源；注册也不保证任何对等方愿意建立连接。长期未使用或需回收的资源，通过公开 PR 和联系原维护者处理，不设置自动到期删除任务。

`policy: open` 允许普通维护者申请资源；`closed` / `reserved` 禁止成员分配。当前校验器也会拒绝把已有分配所在的池直接改为非开放状态，需管理员先协调迁移或修改政策实现。

## 所有权

`mnt-by` 指明对象维护者，`auth` 保存 Ed25519 公钥。维护者自行保管私钥；所有权转移及失钥恢复必须通过管理员核实并签名。没有旧密钥时，不接受仅凭修改后的公钥自证所有权。

当前同一个路由前缀只登记一个 origin ASN，且路由对象的维护者必须是已分配网段的维护者，并与 origin ASN 的维护者有交集。暂不支持跨维护者的路由委托和多 origin 登记。

## 公开信息

注册数据及邮件地址、Git 提交、PR 讨论公开可见，并可能被他人复制。请仅提交有权公开的内容。数据删除不能保证抹除 Git 历史和外部副本；不要提交地址、证件、私钥等无关资料。
